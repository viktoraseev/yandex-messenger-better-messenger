# Better Messenger — runtime prototype

Заменяет штатные **Link to message** / join-ссылки единственным пунктом **Link to message**, который копирует прямую ссылку на сообщение. Он всегда первый в меню: в обычных чатах, ответах, шапке треда и отдельном меню карточек раздела Threads. Если Messenger действительно не открывает меню, показывает резервную кнопку.

Исходники и загрузчик лежат вне `.app`. Приложение, его подпись, профиль и сообщения не изменяются. npm-зависимостей нет; нужен Node.js 22+.

## Запуск без терминала

Можно собрать отдельный **Better Messenger.app** и открывать его из Finder или Dock. Для сборки нужны macOS и Xcode Command Line Tools:

```sh
npm run build:launcher
```

Результат — `dist/Better Messenger.app`. Он содержит копию текущего патча и не зависит от расположения worktree после сборки. Node остаётся внешним: при сборке можно указать стабильный путь, например `-- --node /opt/homebrew/bin/node`. Если Node удалён или путь изменился, launcher надо пересобрать. Существующий `.app` сборщик не перезаписывает; для следующей сборки укажи новый `--output` или убери прежний результат вручную.

Launcher запускает Messenger с inspector только если тот ещё не работает. Уже запущенный Messenger не закрывается. Повторное открытие выводит его на передний план, не создавая второго помощника. После обычного Quit Messenger не запускается сам. Новый запуск происходит, только когда ты явно открываешь Better Messenger или кликаешь по ссылке на чат в браузере (см. «Открытие ссылок из браузера»).

Если после обновления или обычного запуска inspector недоступен, приходит уведомление с просьбой штатно закрыть Messenger и открыть Better Messenger. Автоматического закрытия нет, даже если предполагается, что звонок закончился. Уведомление отправляется один раз на процесс; macOS может скрыть его своими настройками. Когда inspector снова доступен, патч возвращается автоматически.

Launcher работает без отдельного меню отключения. Автозапуск при входе в macOS не устанавливается. Диагностический лог находится в приватной временной папке текущего пользователя `better-messenger-<uid>`; путь к нему показывается при ошибке запуска. В лог не записывается переписка.

## Запуск

Штатно закрой Messenger, затем из этой директории:

```sh
npm start
```

По умолчанию запускается `/Applications/Yandex Messenger.app` с основным инспектором на **127.0.0.1:9231**. В интерфейс внедряется внешний модуль, без открытия DevTools и без отключения sandbox/contextIsolation.

CLI остаётся работать: восстанавливает подключение после перезапуска процесса. Внедрённый код самостоятельно подключается к новым окнам и повторяется после загрузки страницы.

```sh
npm run inspect
npm run status
npm run reload
npm run stop
npm test
```

`reload` применяет изменённые исходники без перезапуска приложения. `stop` удаляет пункты и обработчики, а актуальный supervisor завершает работу; сам Messenger остаётся открытым. Ctrl+C только отключает supervisor: уже внедрённый модуль продолжает работать до `stop` или выхода из Messenger.

Если приложение уже запущено с нужным инспектором:

```sh
npm run attach
```

После `stop` инспектор остаётся открыт до обычного перезапуска приложения. Чтобы полностью убрать дополнительную поверхность доступа, закрой Messenger и запусти его обычным способом.

## Ссылки

По умолчанию копируется прямая корпоративная ссылка:

```text
https://messenger.360.yandex.ru/#/chats/<encoded-chat-id>/<message-timestamp>
```

Для ответа сохраняется идентификатор самого треда. Для первого сообщения в шапке берётся родительский чат и timestamp исходного сообщения. Не требуется `invite_hash`; получателю всё равно нужен доступ к чату. Timestamp — идентификатор в микросекундах, не дата из текста сообщения.

Другую поверхность нужно указать явно:

```sh
npm start -- --base-url https://messenger.example.org --route-format pathname
```

Штатные link/join-пункты скрываются только после успешного добавления новой ссылки. При `stop` они восстанавливаются. Дублирования нет; tooltip — `Copy direct link to this message`.

## Открытие ссылок из браузера

Сайт messenger.360.yandex.ru больше не открывает десктопный Messenger и уводит в Телемост. Связку восстанавливает Chrome-расширение [yandex-messenger-telemost-messenger-fix](https://github.com/viktoraseev/yandex-messenger-telemost-messenger-fix). Оно останавливает загрузку страницы `https://messenger.360.yandex.ru/#/chats/...` и открывает ту же ссылку со схемой `better-messenger:`.

Launcher регистрирует схему `better-messenger://`:

- Принимаются только ссылки на чаты (`#/chats/...`) на хосте из `--base-url`. Остальные игнорируются.
- Ссылка передаётся в Messenger как `ychat://<host>/#/chats/...`. Эту схему регистрирует Yandex Messenger.app, и ссылка уходит в уже запущенный процесс, второй не стартует.
- Если Messenger работает с патчем, ссылка открывается сразу. Если Messenger закрыт, launcher запускает его так же, как при повторном открытии Better Messenger, и передаёт ссылку после установки патча.
- Если Messenger запущен, но патч за 30 секунд так и не появился (например, Messenger стартовал без inspector), ссылка всё равно открывается. Если Messenger не запустился, ссылка отбрасывается, а запись об этом остаётся в системном логе.

## Как устроено

- `src/cli.mjs` — запуск, подключение, повторное подключение, reload/status/stop.
- `src/inspector.mjs` — небольшой CDP-клиент на встроенном WebSocket; только numeric IPv4 loopback, с проверкой установки Messenger.
- `src/injection.mjs` — lifecycle-hook основного процесса; `webContents.executeJavaScript` внедряет модуль в главное окно.
- `src/renderer.mjs` — распознавание меню по `message-menu`/`yamb-message-menu`, ARIA и меткам `thread-context-menu-*`; добавление первым в настоящий скролл-контейнер Orb-меню и обратимое скрытие старых ссылок.
- `src/message.mjs` — чтение идентификаторов из React Fiber и формирование ссылки; никакого чтения текста переписки или обращения к Messenger API.
- `src/asar.mjs` — только чтение версии и Electron fuses, без извлечения/перепаковки архива.

## Обновления и ограничения

Новые релизы не стирают эти исходники. Внедрение не зависит от webpack module ID, хешей файлов или минифицированных имён функций. Но React Fiber — внутренний интерфейс: после существенной переделки UI может потребоваться поправить адаптер.

После обычной перезагрузки окна модуль устанавливается автоматически. После перезапуска процесса supervisor переподключается, **если новый процесс сохранил параметр `--inspect`**. Если updater запустит приложение без него, нужно штатно закрыть Messenger и снова открыть Better Messenger либо выполнить `npm start`. Launcher уведомляет об этом, но сам приложение не закрывает. LaunchAgent пока не устанавливается.

Проверено подключение к установленному Messenger **3.31.0**, интеграция пункта в его Orb-меню и синтетические случаи для ответов/шапки треда. Пользователь подтвердил появление пункта во всех проблемных местах. Переход по ссылкам проверяется отдельно: прототип не выдаёт права на закрытый чат. Встроенная клавиатурная коллекция Orb не знает о новом DOM-элементе; сам пункт доступен по Tab и активируется Enter/Space, но стрелочная навигация может его пропускать.

## Безопасность

Инспектор позволяет локальным процессам исполнять код в Messenger и получить доступ к его сессии. Даже loopback — дополнительный риск. Не публикуй порт, не проксируй его и не подключай непроверенный код. Прототип не читает токены, не выводит содержимое переписки и не принимает команды из сообщений. Только явный клик пользователя записывает ссылку в clipboard.
